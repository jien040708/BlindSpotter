# BlindSpotter

BlindSpotter is a graph neural network research project for predicting
blind-zone risk from IMPTC intersection trajectory data.

The main research question is:

```text
Given the current frame or a short sequence of past frames,
can a model predict whether a blind-zone node will become risky for VRUs?
```

The goal is not simple visible-object detection. Instead, the project models
the blind zone itself as a graph node and predicts whether a vulnerable road
user (VRU), such as a pedestrian, cyclist, or e-scooter rider, is likely to
emerge near that blind zone.

The current `main` branch contains the latest reproducible code, documentation,

## Final Experiment Summary

The final comparison uses IMPTC `set01` to `set05` under the same pipeline:

```text
IMPTC set01-set05
-> trajectory parsing
-> frame-level graph generation
-> blind-zone node labeling
-> scene-level train/validation/test split
-> model training
-> AUROC, AUPRC, F1-score evaluation
-> research visualization generation
```

The three compared models are:

```text
EIGAT single-frame
MR-GCN single-frame
Social-STGCNN / ST-GCN temporal model with 5-frame history
```

The main metrics are prioritized as:

```text
1. AUPRC
2. Best F1 / F1-score
3. AUROC
```

AUPRC is the most important metric because positive blind-zone risk labels are
highly imbalanced.

## Setup

Install dependencies:

```bash
pip install -r requirements.txt
```

```bash
export KMP_DUPLICATE_LIB_OK=TRUE
export DEVICE=cpu
```

## Quick Reproduction

Run the full set01-set05 experiment:

```bash
KMP_DUPLICATE_LIB_OK=TRUE \
DEVICE=cpu \
SETS="1 2 3 4 5" \
EPOCHS=20 \
TEMPORAL_EPOCHS=20 \
MAX_FRAMES=500 \
FRAME_STRIDE=5 \
./scripts/run_imptc_sets_experiments.sh
```

For a faster smoke run:

```bash
KMP_DUPLICATE_LIB_OK=TRUE \
DEVICE=cpu \
SETS="1 2" \
EPOCHS=2 \
TEMPORAL_EPOCHS=1 \
MAX_FRAMES=100 \
FRAME_STRIDE=10 \
./scripts/run_imptc_sets_experiments.sh
```

Supported set formats:

```bash
SETS="1 2 3"
SETS="01 02 03"
SETS="set1,set2,set3"
```

To skip temporal model training:

```bash
RUN_STGCN=0 SETS="1 2 3" EPOCHS=5 ./scripts/run_imptc_sets_experiments.sh
```

## Data Layout

Official IMPTC archives are downloaded into:

```text
data/downloads/
```

Extracted sequence data is placed under:

```text
data/imptc_sequences/
```

The runner builds a selected symlink root for each experiment:

```text
data/imptc_selected/set01_set02_set03_set04_set05/
```

If using manually prepared data, use this structure:

```text
data/sample/
├── set1/
│   ├── 0000_...
│   └── 0001_...
├── set2/
│   └── 0050_...
└── set3/
    └── 0100_...
```

Each sequence folder must contain:

```text
<sequence>/
├── vehicles/
│   └── <track_id>/track.json
└── vrus/
    └── <track_id>/track.json
```

Run with local sample data:

```bash
SOURCE_ROOT=data/sample \
DOWNLOAD_IMPTC=0 \
SETS="1 2 3" \
./scripts/run_imptc_sets_experiments.sh
```

## Pipeline Details

The main runner is:

```text
scripts/run_imptc_sets_experiments.sh
```

It performs:

```text
1. Download selected IMPTC archives if needed
2. Build selected sequence root
3. Convert trajectories into frame graph JSON files
4. Create scene-level train/validation/test split
5. Train EIGAT single-frame baseline
6. Train MR-GCN single-frame comparison
7. Train ST-GCN temporal comparison
8. Aggregate metrics and generate figures
```

The split is scene-level, not frame-level:

```text
train = 70%
validation = 15%
test = 15%
seed = 7
positive scene ratio preserved when possible
```

Scene-level splitting prevents frames from the same scene appearing in both
train and test.

## Graph Representation

Each frame graph stores:

```text
node_ids
node_types
x
edge_index
edge_attr
edge_type
blind_node_indices
blind_y
```

Main node types:

```text
reference_vehicle
vehicle
pedestrian
cyclist
e_scooter
occlusion_zone
```

Node features include:

```text
position
velocity
heading
object type
distance and angle to reference vehicle
visibility
occluder flag
VRU flag
```

Edge features include:

```text
distance
relative velocity
relative heading
time-to-collision
visibility blocking
```

MR-GCN uses relation IDs through `edge_type`. EIGAT and ST-GCN use continuous
edge features for message passing or attention.

## Individual Commands

Download IMPTC archives:

```bash
IMPTC_PARALLEL_PARTS=12 \
./scripts/download_imptc_sequences.sh \
  imptc_set_01.tar.gz \
  imptc_set_02.tar.gz
```

Preprocess graph JSON:

```bash
python scripts/preprocess_sample.py \
  --root data/imptc_sequences \
  --output outputs/graphs_imptc_set01_set02 \
  --max-frames 500 \
  --frame-stride 5 \
  --neighbor-radius 30
```

Create scene split:

```bash
python scripts/create_scene_split.py \
  --summary outputs/graphs_imptc_set01_set02/preprocess_summary.json \
  --output outputs/splits/imptc_set01_set02_scene_split.json \
  --train-ratio 0.7 \
  --val-ratio 0.15 \
  --test-ratio 0.15 \
  --seed 7
```

Train EIGAT:

```bash
python scripts/train_single_frame_gat.py \
  --model eigat \
  --graphs outputs/graphs_imptc_set01_set02 \
  --scene-split outputs/splits/imptc_set01_set02_scene_split.json \
  --output outputs/models/imptc_set01_set02/eigat_single_frame.pt \
  --metrics-output outputs/models/imptc_set01_set02/eigat_single_frame.metrics.json \
  --epochs 12 \
  --selection-metric auprc \
  --device cpu
```

Train MR-GCN:

```bash
python scripts/train_mrgcn.py \
  --graphs outputs/graphs_imptc_set01_set02 \
  --scene-split outputs/splits/imptc_set01_set02_scene_split.json \
  --output outputs/models/imptc_set01_set02/mrgcn_single_frame.pt \
  --metrics-output outputs/models/imptc_set01_set02/mrgcn_single_frame.metrics.json \
  --epochs 12 \
  --selection-metric auprc \
  --device cpu
```

Train ST-GCN:

```bash
python scripts/train_stgcn.py \
  --graphs outputs/graphs_imptc_set01_set02 \
  --scene-split outputs/splits/imptc_set01_set02_scene_split.json \
  --output outputs/models/imptc_set01_set02/stgcn_temporal_h5_t1.pt \
  --metrics-output outputs/models/imptc_set01_set02/stgcn_temporal_h5_t1.metrics.json \
  --history 5 \
  --prediction-horizon 1 \
  --epochs 4 \
  --selection-metric auprc \
  --device cpu
```

Aggregate results:

## Known Limitations

1. The reference vehicle is selected heuristically because IMPTC does not define
   an explicit ego vehicle for this task.
2. Blind-zone nodes are generated by a simplified occluder heuristic, not by a
   full camera/LiDAR visibility polygon.
3. `blind_y` is a proxy label for future VRU emergence near a blind zone. It is
   not a direct collision-risk or injury-severity label.
4. Positive labels are imbalanced, so threshold choice matters. The project uses
   validation threshold sweeps and reports best-F1 in addition to F1@0.5.
5. Current temporal modeling uses a short 5-frame history. Longer horizon
   sweeps and map-aware features remain future work.
